# Purpose

This document defines the official visual language used across all NEXUS Research Lab assets.

Its purpose is to guarantee visual consistency between documentation, diagrams, repositories, presentations, websites and future software interfaces.

The Visual Design System complements the Brand Book by defining implementation rules rather than institutional identity.

---

# Design Philosophy

Every visual element produced for NEXUS shall communicate:

• Scientific rigor

• Structural clarity

• Technical precision

• Academic professionalism

• Long-term maintainability

Visual design must support understanding rather than decoration.

---

# Visual Language

The NEXUS visual language is based on four principles:

1. Modular composition

2. Geometric precision

3. Hierarchical organization

4. Minimal visual noise

Every illustration should appear engineered rather than illustrated.

---

# Graphic Style

Preferred style:

✓ Flat vector graphics

✓ Monochrome or restrained color usage

✓ Consistent line weight

✓ Geometric construction

✓ High negative space

Avoid:

✗ Photorealistic graphics

✗ 3D effects

✗ Heavy gradients

✗ Cartoon illustrations

✗ Decorative textures

✗ Excessive shadows

---

# Grid System

All diagrams should be constructed using an invisible grid.

Preferred spacing:

8 px

16 px

24 px

32 px

64 px

The same spacing scale shall be reused throughout all visual assets.

---

# Geometry

Preferred shapes

• Circle

• Rounded rectangle

• Hexagon (only when meaningful)

• Straight connectors

• Orthogonal layouts

Avoid unnecessary irregular geometry.

---

# Line Style

Default stroke

2 px

Large diagrams

3 px

Corner radius

8 px

Connector style

Straight or orthogonal

Arrowheads

Simple filled triangle

Consistency is mandatory across every illustration.

---

# Color Application

Primary usage

Deep Navy

Secondary usage

Blue

Accent usage

Emerald

Neutral backgrounds

White or very light gray

Color must communicate hierarchy, never decoration.

---

# Typography in Graphics

Typeface

Inter

Weights

Regular

Medium

SemiBold

Avoid more than three font weights in the same composition.

---

# Diagram Principles

Every diagram should:

✓ Read from left-to-right or top-to-bottom

✓ Have a single visual focus

✓ Minimize crossing lines

✓ Clearly distinguish hierarchy

✓ Preserve readability when scaled

---

# Illustration Principles

Illustrations should represent:

• systems

• workflows

• research

• architecture

• documentation

rather than people, robots or consumer technology.

Artificial intelligence should never become the dominant visual element.

---

# Module Graphics

Each architectural module shall have its own dedicated vector illustration.

These illustrations must:

- follow the same construction grid;
- use identical stroke widths;
- share visual proportions;
- preserve stylistic consistency;
- remain recognizable in monochrome.

---

# Asset Formats

Master format

SVG

Distribution formats

PNG

PDF

WEBP

Raster graphics should always originate from the SVG master.

---

# Accessibility

Visual assets should maintain readability under:

- grayscale printing;
- projector presentation;
- reduced resolution;
- dark and light backgrounds.

---

# Repository Assets

Every official repository should include:

✓ Institutional logo

✓ Official banner

✓ Architecture diagram

✓ Workflow diagram

✓ Module graphics

✓ README illustrations

All assets shall originate from this Visual Design System.

---

# Future Evolution

Future versions may define:

- UI component library

- Website design system

- Presentation templates

- Scientific poster templates

- Icon library

- Animation guidelines

without altering the principles defined in this document.

---

# Scientific First

Whenever a design decision involves a trade-off between aesthetics and scientific clarity, scientific clarity shall always prevail.

Visual elements exist to improve understanding, not to attract attention.
